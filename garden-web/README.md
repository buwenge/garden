# 小院子前端展示页 🌿

给「小院子」做的可视化页面：可爱温馨的绿色系界面，打开手机就能看到
四块菜畦、小动物、篮子、手账和院子天气，也可以直接点按钮浇水、播种、收获、
摸摸、投喂、陪玩——有一点点放置类小游戏的感觉。

## 长什么样 / 有什么

- **单屏设计（旅行青蛙式）**：除了弹层没有任何滚动——天檐、院子全景、底部道具栏
  一屏装完；所有信息和操作都通过底部弹层（sheet）呈现。
- **天檐**：按真实时间切清晨/白天/黄昏/夜晚；夜里升月亮、飘萤火虫，
  真实下雨时天上真的掉雨（天气数据源和院子是同一套）。
- **小药丸**：天气（点击看详情）和实时时钟飘在天檐下。
- **院子此刻（全景图）**：手绘水彩背景 + 贴纸图层——四株作物按生长阶段贴纸站进
  一号大田的四个角位，小动物按 `spot` 常驻点落位（白天坐姿、夜里趴姿），
  全部可点：点田开菜畦弹层、点动物开动物弹层、点门廊篮子开篮子弹层、
  点信箱开手账弹层。夜晚整院蒙蓝调，下雨叠雨丝层。
- **底部道具栏**：光景（agent 写的院子信笺）/ 手账 / 去逛逛 / 浇全部。

## 运行

```bash
cd garden-web
python3 server.py            # 默认只监听 127.0.0.1
# 本机访问：ssh -L 8137:127.0.0.1:8137 root@<主机> 后开 http://127.0.0.1:8137/
```

环境变量（都有默认值）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `GARDEN_WEB_PORT` | `8137` | 端口 |
| `GARDEN_WEB_HOST` | `127.0.0.1` | 监听地址（安全规范：默认只绑回环，外部访问走 SSH 隧道） |
| `MINI_YARD_HOME` | 本仓库根目录 | home.py / garden.py 所在目录（数据源） |

对外访问建议统一走一个反代路径（如 `/garden/`）。nginx 在转发页面、素材和 API
之前，先用 `auth_request` 向站点现有登录中间件验证登录态：已登录直接进入，
未登录回 `/login`。永久钥匙不会写入源码、URL、浏览器存储或 GitHub。
站点配置可直接参考同目录的 `nginx-location.conf.example`；这些 location 要放进
主站现有的 `server {}` 中，不能把 `/garden/` 单独暴露。

`server.py` 自身只监听 `127.0.0.1`，信任同机反向代理；禁止把 8137 端口直接暴露
到公网。SSH 隧道访问属于本机管理通道，不经过网页登录校验。

## 架构（刻意保持简单）

```
index.html   单文件前端（无构建、无依赖，纯原生 JS/CSS）
server.py    标准库 HTTP 服务器，三个入口：
  GET  /            页面本体
  GET  /api/state   in-process 调 garden.py 的官方快照
                    (crop_snapshot / active_entries / journal_snapshot …)，
                    不做任何生长逻辑，只读 + 结算，和 `home 院子 查看` 等价
  POST /api/action  把 {"cmd":"浇水 1"} 这类指令白名单校验后
                    原样转发给真正的后端：`home 院子 …`
  GET  /assets/*.png  水彩背景与贴纸静态素材（仅 png，禁目录逃逸，缓存 1h）
```

- 所有院子规则（生长、亲密、季节、天气联动）都留在 `garden.py`；前端只负责美。
- `/api/state` 的 plots 字段基于 `garden.crop_snapshot()` 的结构扩展，将来要接入
  自己的正式前端（比如一个 WebSocket 客户端），直接复用 `garden.frontend_state_event()`
  或本接口的字段即可。
- 指令白名单：查看/逛逛/记录/手账/篮子/播种/浇水/除虫/修剪/松土/施肥/清理/收获/
  投喂/摸摸/陪玩/取名/做点吃的/送给user。参数只允许中英文数字，防注入。
- nginx `/garden/` 必须保留站点的 `auth_request`；它是公网鉴权边界，不能只保留反代。
